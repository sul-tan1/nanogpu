# NanoGPU

NanoGPU is a programmable 2D renderer and vector processor.
Two 8-bit SIMD lanes run a host-loaded program of one to four instructions.
In graphics mode, on-chip counters generate the `(x, y)` coordinates of a
rectangle on a 64 × 64 canvas. In compute mode, the host supplies two pairs of
numbers to the same lanes. Each lane returns an 8-bit result.

The design was routed in one digital Sky130A Tiny Tapeout tile at a 10 MHz
target. See the [verification report](docs/verification.md) for timing, area,
and fabrication status.

## See it in action

<img src="docs/assets/nanogpu-demo.png" width="256" height="256" alt="64 by 64 grayscale gradient with a patterned inset rectangle, generated by NanoGPU in simulation">

The simulated chip shades the background with `(x + y) >> 1`, then runs a
different program over the inset rectangle. The host places the returned bytes
into an image and saves it as a PNG. The same program that draws the gradient
also averages two pairs of numbers in compute mode. The full-frame gradient
takes 10,246 clock cycles, including command and result transfers.

## Run the simulation

Clone the repository using Git:

```sh
git clone https://github.com/sul-tan1/nanogpu.git
cd nanogpu
```

On Windows x64, download `oss-cad-suite-windows-x64-20261120.tgz` to your
Downloads folder. The setup command extracts the toolchain and installs the
Python test dependencies locally. [OSS CAD Suite release](https://github.com/YosysHQ/oss-cad-suite-build/releases/tag/2026-11-20)

```powershell
.\tt.cmd setup
.\tt.cmd test
Start-Process .\test\output\nanogpu.png
```

Expect `TESTS=4 PASS=4 FAIL=0`. For **Ubuntu or WSL**, an existing Windows toolchain,
or opening waveforms, see the [tooling guide](docs/windows-and-github.md).

## Try a different program

Change `pattern` in `shared_program_demo` and rerun the simulation to see a
different inset. Try `[XOR]` for a repeating bit pattern or `[MAX, ADD, ADD, ADD]`
for a bright gradient. In compute mode, the host can send grayscale pixel pairs and use
`MAX` to keep the brighter pixel at each position. See the [instruction set
and host protocol](docs/info.md) and [test source](test/test.py).

## Project files

| File | Purpose |
| --- | --- |
| `docs/project-plan.md` | Design constraints and remaining architecture experiments. |
| `src/nano_gpu.v` | Command decoder, scan counters, sequencer, and two arithmetic lanes. |
| `src/project.v` | Map the design onto Tiny Tapeout pins. |
| `test/test.py` | Shared functional tests for RTL and the generated gate-level netlist. |
| `info.yaml` | Project title, author, pinout, top module, source list, clock, and tile size. |
| `test/Makefile` | Keep `PROJECT_SOURCES` aligned with `info.yaml`. |
| `docs/info.md` | Datasheet, host protocol, and example transactions. |
| `src/config.json` | Physical implementation configuration and 100 ns clock period. |

GitHub Actions runs lint, RTL and gate-level simulation, GDS generation,
precheck, documentation, and layout publication. The optional FPGA workflow
runs manually. See the [tooling guide](docs/windows-and-github.md) for the
artifacts from each job.

The interface, configuration, and workflows derive from the
[Tiny Tapeout Verilog template](https://github.com/TinyTapeout/ttsky-verilog-template).
